# PP 钢琴键盘 × B站 Toy · 社区网页版产品规格与发展路线

**版本**：交接草案 v1.0（2026-10-28）\
**读者**：本地 Codex、前端/Go 开发者、测试及后续运维\
**准绳**：这是**目标与实施路线**，不是已实现功能承诺。当前源码完成度以 `README.md`、`BUILD-RESULT.md` 和实际运行测试为准。

## 0. 一句话定位

让用户“打开即看到钢琴”，围观他人弹奏、排队获得 5 分钟的公共舞台；也能在自己的房间安静练琴，寻找或发布 MIDI，并持续积累练习成果。**以钢琴演奏为核心，社区服务围绕钢琴，而非把钢琴埋在社交 UI 里。**

### 产品边界

- **桌面 PP 钢琴键盘**：专业本地演奏、高品质 SoundFont、硬件 MIDI、录制和深度练习；Web/Toy 的交互与视觉优先对标现有 App，复用纯前端代码。
- **Toy 网页版**：无需安装、触控优先、随开随弹、即时围观和分享；依托浏览器音频和远程 Go 服务。
- **Go 社区服务端**：负责可信身份、公开/私密琴房、排队独占席位、音符广播、MIDI 文件、审核、练习记录。
- **非目标**：第一阶段不做视频/语音直播、复杂关注关系、金币/充值、多人同时合奏、官方曲谱授权平台、完整乐理教学和多机分布式排队。

### 三种关键用户场景

1. **围观者**：进入 Toy 即可看到一台可视化钢琴 → 浏览实时大厅 → 听到当前玩家弹奏/看琴键反馈 → 想上台则登录并排队 → 轮到自己自动获得控制权 → 5 分钟结束或主动下场。
2. **练习者**：创建公开或私密琴房 → 使用完整键盘、瀑布流、延音与自己的 MIDI/音源 → 公开房可被随机围观，私密房用带权限的邀请链接 → 同步自己的练习记录。
3. **曲目作者/学习者**：上传 `.mid/.midi` → 填曲名、作曲者、难度、标签、介绍、公开权限 → 后台解析轨道、音符、小节、拍号、速度与调号 → 私密作品只给自己 → 公开作品审核通过后可搜索/试听/跟弹 → 记录练习次数、时长和最近练习时间。

## 1. 视觉及体验规范（对标 Desktop，而不是照搬窗口壳）

- 延续桌面版的**深灰/黑灰主色、克制的蓝/紫强调色**；键盘布局、左右手配色和瀑布流绘制坐标尽可能直接复用。桌面视觉应保持简洁专业、减少不必要弹窗和夸张游戏化特效。
- 主屏幕**钢琴舞台始终是主体**；在线功能放顶部入口/侧面板。进入大众房后在舞台上显示“当前演奏者、排队位次、倒计时、在线人数、让位”，不遮挡大部分键盘。
- 观众看到同一台琴键弹起/按下、瀑布流和当前踏板效果，**不应误以为可以控制**。观众琴键不可交互，但本地自由演奏入口仍然明确。
- 台上用户视觉焦点是剩余时间与钢琴，不出现过度提示；倒计时临近结束时轻量提示，如 30/10 秒，交接时清音并显示下一位。
- 手机首选**横屏沉浸**，若用户未授权/设备不支持则竖屏正常布局，不出现超出安全区的按钮；触摸支持多点和滑奏；锁定触摸滚动避免误拖，页面失焦/指针取消释放所有按键。
- 平板/桌面显示更多琴键，手机按可操作性缩减可见音域并提供简洁调节；不是把 88 键缩成不可点击的细线。
- 页面首屏最少依赖：不能等待 100MB SF2 下载完成才展示钢琴；音源须可回退。Web Audio 解锁由用户手势完成。
- 支持连接失败降级：**网络不可用时本地钢琴、MIDI 导入、瀑布流、录制仍能使用**，在线面板清楚显示离线原因。

### 1.1 主屏幕交互流程

```
启动 / 展示钢琴
    ├─ 本地自由演奏 / MIDI 播放 / 跟弹 / 录制（网络不需要）
    └─ 在线
        ├─ 大众琴房：围观 → 登录 → 排队 → 上台 ≤5分钟 → 让位或自动下场
        ├─ 自建琴房：公开 / 私密 → 邀请或随机围观 → 房主独奏
        ├─ MIDI 工坊：公开检索 / 我的私密 / 上传审核 / 跟弹
        └─ 我的练习：历史 / 总时间 / 最近练习 / 继续练习
```

## 2. 大众琴房：产品与服务端裁定规则

**概念**：全服唯一公共大厅 `roomId=lobby`，任意访客可围观；同一时刻**只允许 1 人演奏**。所有参与者通过各自浏览器音源还原统一 MIDI 事件，不是直播 PCM 音频流。

| 状态 | 谁有权限 | 系统行为 |
|---|---|---|
| 没有演奏者 | 所有访客看，登录者排队 | 队列第一位在线者可获席；大厅保留历史观众连接 |
| 观众 | 只接收 note/pedal/clear | UI 禁止发出音符；服务端拒绝越权消息 |
| 排队中 | 登录者可取消排队 | FIFO，去重，更新队列位置与当前预计候场人数 |
| 已上台 | 当前账号对应的席位 | 服务端独占 5 分钟；前端只是倒计时显示；可主动 `seat.leave` |
| 到期/主动让位 | 无人可继续占用旧席 | 服务端立即释放按键与踏板，分配下一位，广播快照 |
| 网络断开 | 按后端权威判断 | 排队者和上台者最多 15 秒宽限；超时离队/释放席位 |
| 重连 | 只恢复被认证的同账号 | 重取 `snapshot`/`room.sync`，恢复音符与队列，不重置 5 分钟 |

**进一步完善（当前需要确认/实施）**：

- 空队列时演奏者 5 分钟结束后成为观众；如想再弹应重新排队，不能霸台。
- 台上用户跨设备同时连接时，应由**同一账号的一个已授权连接**持有输出权，防止多连接互相发送 `note.off` 导致串音；单账号同时上台策略应在服务端一致实现。
- 排队作弊：重复入队/刷新都不重排、不能跳队；服务器用 Session 校验身份，登录/WS 限流。
- **避免空台浪费**：后续引入可配置的无人操作提醒与自动下场（如 60 秒没有音符活动），但不能误伤长休止符/慢曲，首版暂不强行启用。
- 音符安全：限制 note=0–127、velocity=1–127、允许的 controller、单连接消息速率、最大 WS 帧，收到断开/换人/过期必须 `clear`，包括 sustain 全部释放。
- 观众延迟：广播附单调 `seq` 和 `serverTime`，通过 heartbeat/pong 估时钟偏移，短抖动缓冲同步“声音与画面”；高延迟或丢包时请求快照而不是继续播放旧音符。
- 公平性可观测：记录最小必要匿名化事件指标（等待时间、交接次数、重连率），**不记录玩家乐曲原始长序列或敏感登录信息**。

### 2.1 大众琴房验收场景

1. A/B/C 同时排队，A、B、C 按加入顺序上台；A 让位后 B 立即接手；已过期 A 发音符被拒绝。
2. 观众 D 构造 `note.on` 或修改前端 `isPerformer`，服务端不广播、不改变状态。
3. A 按住多个琴键和延音时掉线，观众马上清音；15 秒内 A 同账号重连仍只剩**原来**的倒计时；超时下一位接手。
4. 切换前后台或短暂丢包后观众调用 `room.sync`，按下键/踏板状态与服务端一致；旧 `seq` 被忽略。
5. 大量观众和慢连接不应使演奏事件长时间阻塞主广播；必须做实际负载测试后才能承诺承载量。

## 3. 自建琴房

- 默认房主独奏，观众只看；不受大众琴房 5 分钟限制。**不设计多人合奏**，避免权限复杂度增长。
- 创建时填写标题、公开/私密；公开房可搜索/列出/随机围观，私密房不出现在公开列表。
- 私密房通过房间 ID + 高熵邀请凭证访问，服务端仅存凭证哈希；不能仅凭猜测房间 ID 访问。房主可重置凭证、调整公开/私密、关闭房间，旧凭证失效。
- 房主不在线时，从随机房列表暂时隐藏；房主再次进房可恢复。退出/关闭时观众清音并获得状态提示。
- **随机围观**只选在线、公开、未关闭、有房主演奏资格的房间；可以优先避开连续重复推荐（后续）。
- 公开标题/描述必须经过审核与风控；管理员需具备隐藏/关闭能力；禁止因私密房创建错误导致公开列表泄漏。
- 未来可加**练习邀请**、房主教学提示、关注与收藏；本轮不进入范围。

## 4. MIDI 工坊：曲目与审核

### 4.1 曲目字段

| 类型 | 字段 | 规则 |
|---|---|---|
| 用户填写 | `title` | 必填，最长 120 字；公开展示前安全检测 |
| 用户填写 | `composer` | 原作者/作曲者；非 MIDI 自动识别；允许“未知” |
| 用户填写 | `description` | 简介、版本信息、演奏建议 |
| 用户填写 | `difficulty` | 1–5，由上传者主观选择，未来加自动建议但不覆盖人工 |
| 用户填写 | `tags` | 最多 8 个，去重、去空白、服务端规范化 |
| 用户填写 | `public` | 默认私密；申请公开须确认分享权利且审核通过 |
| 自动解析 | `trackCount`, `trackNames`, `noteCount` | MIDI 轨道及音符数，区分真实含音符轨 |
| 自动解析 | `tempoBpm`, `durationMs` | 读取 Tempo 元事件，完整时间轴推导实际时长 |
| 自动解析 | `timeSignature`, `measures` | 拍号和**估计**小节数，遇拍号变化需明确算法 |
| 自动解析 | `keySignature` | 读取 MIDI Key Signature 元事件；**缺失不是自动和声推断** |
| 系统字段 | `sha256`, `fileSize`, `reviewStatus`, `ownerId` | 去重/安全、所有权、审核状态与文件权限 |

### 4.2 用户旅程

- 上传 `.mid/.midi` → 表单校验、音符/事件/轨道安全限制 → 原文件持久化 → 服务端解析并返回乐理摘要 → 可设私密，公开须先审核。
- 公开列表只显示**审核通过**的曲目；支持名称/作曲者/标签/难度、分页、时间排序；曲目详情进入现有瀑布流播放/跟弹（不要另做播放器）。
- “我的上传”包括待审、私密、已通过、被拒绝和下架；允许合法的标题/标签修改，改公开内容需重新进入审核；被封锁条目不能一键恢复公开。
- 私密下载/详情由服务端判断 owner 身份，文件名随机，不能把 OSS/磁盘路径当成公开 URL；下载需要鉴权或带有效期的签名链接。
- 重复上传、存储配额、删除与引用历史的行为要明确：删除 MIDI 不删除练习日志快照，实际文件可在安全的后台清理。
- **版权与治理**：MIDI 演奏数据也可能涉及作品著作权；用户必须确认分享权利，平台要有举报/下架/申诉流程，不能将 CC0 音源授权误认为曲目版权授权。

### 4.3 验收

- 私密资源 404/403 权限明确，任意其他账号无法下载原文件；URL 猜测与篡改 ID 不能访问。
- 上传恶意/畸形 MIDI 被限制内存、事件数、大小、处理耗时；解析后显示轨道、速度、音符与拍号。
- 无调号元事件时显示“未标注”，不能根据曲名臆测调性。
- 待审核曲目不出现在公开结果；管理员通过后可公开；下架无法通过简单切换状态绕开。

## 5. 练习记录与留存

**设计重点**：帮助用户真正进步，而非做签到系统。

- 记录 `midiId`、标题快照、模式 `play/follow`、开始时间、结束时间、实际有效练习秒数与最近练习时间。
- 服务端核算时长：开始/心跳/暂停/结束按可信服务器时间累计；单次心跳上限避免伪造 10 小时练习。关闭后台/断网应允许少记而非虚构记录。
- 统计：每首曲累计练习时长、次数、上次练习时刻；最近练习列表和“一键继续”，支持移动端查看。
- **建议后续**：记住每首曲上次播放位置、A–B 书签、左右手、变速；可以同步少量配置（Toy 云存储小数据）但 MIDI 二进制仍由服务器/本地管理。
- 误触/短播放（例如只打开试听 2 秒）不应被视为有效练习，可设置最低有效时长阈值作为未来策略。

## 6. 技术架构与数据原则

```
Toy / 普通浏览器 (Vue 3 + Vite)
  ├─ 本地: Keyboard + Canvas Waterfall + WebAudio + IndexedDB
  ├─ Toy Bridge: window.toy, feature detection, container/share/preferences
  ├─ REST HTTPS: account / rooms / MIDI metadata+file / practice / moderation
  └─ WebSocket WSS: join -> lobby/room -> snapshot/seq -> events/heartbeat
                                      |
Go 单体服务 (GORM + Gorilla WebSocket) + 单进程 room hub
  ├─ 应用层: 认证/授权、队列、房间、曲库、审核、练习统计
  ├─ GORM AutoMigrate: users / sessions / rooms / midi_files / practice_logs / reports
  ├─ SQLite (开发/单机) 或 PostgreSQL (后续生产迁移)
  └─ 磁盘 data/midi（后续可换 OSS / S3，不能直接公开私密路径）
```

- **六张扁平表**足够：只保留 `ownerId`、`userId`、`midiId` 普通关联标识，优先在应用层检查权限，不新增关注/评论/分数表。避免把功能封装成微服务。
- `AutoMigrate` 用于初始化和非破坏性迭代；真实生产破坏性变更采用**独立迁移、先备份、再发布**。强制唯一与索引要以实际业务不变量为准。
- **单进程 Hub** 管理实时席位和音符。初期只部署一个实例，不能用不带共享状态的多副本负载均衡；未来大规模并发再引入 Redis/消息总线/分区房间。
- 使用 **B站 Toy SDK** 提供平台 UI/个人有限数据能力，不将 Toy 云存储承担实时消息或 MIDI 文件存储；`toyOpenId` 不提供可信后端登录。当前独立账号系统是临时方案，不得基于用户自报 ID 免登录。
- 前端 API 地址通过构建时 `VITE_API_BASE_URL` 配置，线上必须 HTTPS/WSS；后端设置准确 CORS Origins，反向代理可信 CIDR，上传和认证限流，按最小权限授权。
- 本地音源可能与桌面 MeltySynth 不完全一致；高品质 SoundFont 作为按需选择，不要强制百 MB 初次下载；对 SF2 的分发许可证单独核实。

## 8. 发展路线（按依赖与风险排序）

### P0 · 可运行、可测试（先完成）

- 在可联网环境安装 Go 1.23+/Node 22，生成 `server/go.sum`、`web-toy/package-lock.json`；`go test ./...`、`go build`、`npm run build` 全部成功，并修复真实错误。
- 本地部署服务端 + 两个浏览器，验证大厅 A/B 交接、过期拒绝、断线重连、私密权限、公开审核、练习日志。
- 结构化错误提示/日志；做好 `.env` 范例、敏感配置禁止提交、数据库和上传目录备份。
- 确认 B站 Toy 是否准许连接自有 HTTPS/WSS 地址，手机端音频是否必须再次手势解锁；若不允许需调整部署/产品方案，不得偷偷绕过。

### P1 · 核心体验接近桌面 App

- 对标桌面 App 原有 Vue 组件：关键盘视觉、键位标签、按键反馈、主题、左右手、A–B、谱面/瀑布、录制与力度表现；优先**移植**，少重写。
- 优化音频提前排程、踏板、复音、SF2 解码缓存和 WebView 内存；建立极限 MIDI 和手机音频回归数据。
- 大众琴房 UI：排队位置/联机状态/剩余时间/观众数/断线重连提示与清音过渡，确保操作区适合横屏触控。
- 实施 Toy 容器自适应及 SDK 失败降级，完成 Android/iOS/桌面矩阵验收。

### P2 · 工坊与练习留存

- 曲目列表、搜索和标签筛选、公开审核、曲目详情/试听/跟弹、一键下载/缓存；个人作品编辑、转公开重新审核、举报与治理闭环。
- 每首曲的最近练习、总练习时长、次数、继续练习；增加 A–B 书签及阶段目标（保留简洁 UI）。
- 逐步增加基础 MIDI 乐理分析（速度变化、轨道分组、难度建议），注明算法是启发式，不能当“官方考级”。

### P3 · 社区规模化（使用数据证明需要后再做）

- Redis 房间分布式协调、弹性 WebSocket、日志与指标；音源/CDN 缓存、服务端文件杀伤/审核流水线。
- 收藏、练习歌单、分享练习配置、好友邀请或作者主页，但不要过早引入大型社交关系图。
- 只有在平台提供服务端可验证授权后，才考虑 B站账号免注册绑定。

## 9. 验收门槛与发布原则

**所有阶段统一要求**：必须记录实际编译/test logs、代码变更、测试环境和已知限制。没有安装成功依赖或没有双端联机，不能标成“生产可用”。

| 维度 | 最低验收门槛 |
|---|---|
| 功能 | 自由演奏离线可用；双浏览器可围观/排队/让位；私密曲目不可被越权访问；练习时长可信 |
| 音画 | 演奏者/观众的 note.on/off、踏板与键盘状态一致；切后台/断线后无永久卡音 |
| 性能 | 大曲目导入不崩溃；中端手机不因 UI 抖动造成明显丢音（需实测形成量化目标） |
| 安全 | 密码哈希与 token 管理、准确 Origin、CSRF/跨站限制、上传大小/路径、速率限制、管理员操作日志 |
| 运营 | 公开作品可审核/下架，支持举报；版权说明和隐私政策按实际法律/平台要求完善 |
| 部署 | Linux 真实二进制和 Toy `dist/` 编译通过，备份可恢复，HTTPS/WSS 域名可用 |

**开发优先级**：P0 验证并修真实 Bug → P1 App 体验对齐 → P2 用户留存/曲库完善 → P3 扩容。新增功能必须优先不损伤自由演奏延迟、音符力度、长按踏板和稳定性。
